# Обёртка над Keitaro: создание кампаний и редактор офферов

Тестовое задание. Сервис на FastAPI + SQLAlchemy ходит в Admin API трекера Keitaro (учебный стенд
`keitaro-for-tests.etolegko.com`) и умеет две вещи:

1. **Создавать кампанию** по названию, гео (одна или несколько стран: `DE` или `MX, AU, RO`) и офферу
   (поиск с автокомплитом по ID и названию). У кампании настраиваются домен, группа и источник,
   и создаются два потока:
   * поток 1 (`regular`, схема `redirect`) — фильтр «страна входит в список гео», редирект на `https://google.com`;
   * поток 2 (`default`, схема `landings`) — все остальные уходят на выбранный оффер с долей 100%.
2. **Редактировать офферы** в потоках существующей кампании: добавлять, удалять, возвращать из архива,
   закреплять доли. Правки копятся в черновике обёртки и уходят в Keitaro по кнопке **Push to Keitaro**.

Интерфейс на английском. Потоки в редакторе показаны как в эталонном редакторе из видео:
`Stream: Offers (#2) filter by None, stream_id 139`. Поток без офферов (гео → Google) — только заголовок,
у потока с офферами под заголовком таблица.

Фронт — одна HTML-страница на чистом JS, раздаётся самим FastAPI.

Домен, группа и источник для новой кампании берутся из API Keitaro. Если вариант один (как на учебном
стенде), форма просто показывает его; выпадающие списки появляются, только когда есть из чего выбирать.

## Быстрый старт

Нужен Python 3.10+.

```bash
git clone <repo-url> && cd keitaro-wrapper
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env               # Windows: copy .env.example .env
# впишите в .env свой KEITARO_API_KEY и CAMPAIGN_PREFIX (test_фамилия_)

alembic upgrade head               # создаёт таблицы в БД
uvicorn app.main:app --reload
```

Откройте <http://localhost:8000> — это интерфейс. Swagger с описанием API: <http://localhost:8000/docs>.

### Где взять ключ

Войдите на стенд через GitHub и нажмите «API ключ» в правом верхнем углу админки.

|---|---|---|
| `KEITARO_URL` | `https://keitaro-for-tests.etolegko.com` | Адрес трекера без `/admin_api/v1` |

## Миграции

Схема БД управляется Alembic.

```bash
alembic upgrade head                              # применить все миграции
alembic downgrade -1                              # откатить последнюю
alembic revision --autogenerate -m "описание"     # новая миграция после изменения app/models.py
```

Таблицы:

* `created_campaigns` — кампании, созданные через обёртку: ID в Keitaro, гео (коды через запятую), исходный оффер, ID обоих потоков;
* `stream_offers` — черновик офферов каждого потока: доля, состояние, закрепление, статус
  (`live` — есть в Keitaro, `new` — добавлен, не запушен, `removing` — удалён, не запушен,
  `archived` — удалён из Keitaro, хранится в обёртке) и что лежит в Keitaro после последнего пуша;
* `offer_changes` — журнал действий с офферами: какой поток, действие, состав «до» и «после».

Источник правды по тому, что реально работает, — Keitaro; обёртка хранит черновик, архив и историю.

## Как работает редактор офферов

**Черновик и пуш.** Любое действие (Add, Remove, ввод доли, пин) сразу сохраняется в БД обёртки,
но в Keitaro не отправляется. Пока есть незапушенные изменения, блок потока подсвечен жёлтым,
у новых офферов бейдж `new`, у изменённых — `changed, 33% in KT`. Кнопка **Push to Keitaro** отправляет
весь состав одним `PUT /streams/{id}`. **Discard changes** возвращает черновик к тому, что сейчас в Keitaro.

**Удаление и архив.** Удалённый оффер до пуша остаётся в Keitaro: в обёртке он зачёркнут, с бейджем
`will be removed` и кнопкой **Undo remove**. После пуша оффер пропадает из Keitaro, но остаётся в обёртке
в разделе **Archive** (серым, с датой) с кнопкой **Restore**. Архив открыт по умолчанию, его можно свернуть.
Возвращённый оффер снова становится `new` и попадёт в Keitaro со следующим пушем. Оффер, добавленный
и удалённый до пуша, просто исчезает из черновика.

**Доли и пины.**
* Сумма долей активных офферов должна быть ровно 100%, иначе пуш недоступен.
* При добавлении, удалении или возврате оффера доли пересчитываются поровну,
  остаток от деления получают первые: 3 оффера → 34/33/33.
* Закреплённый (кнопка с булавкой) оффер сохраняет долю при пересчёте; остаток делится между
  незакреплёнными. Например, 18001 закреплён на 70%, добавили два оффера → 70/15/15.
* Хотя бы один активный оффер всегда остаётся незакреплённым, иначе изменения некому принять.
  Поэтому единственный оффер закрепить нельзя, а у последнего незакреплённого кнопка неактивна.
* Если после удаления все оставшиеся офферы закреплены (было два, один закреплён, второй удалили),
  закрепления сбрасываются и доли делятся поровну.
* **Ручной ввод доли.** Остаток делится между остальными незакреплёнными офферами пропорционально
  их текущим долям: было 50/30/20, первому поставили 60 → 60/24/16. Сумма всегда остаётся 100%.
  Максимум поля — 100% минус закреплённые доли; больше ввести нельзя, значение обрежется с подсказкой.
  Если подстраивать некого (оффер единственный или все остальные закреплены), поле неактивно.
* **Split evenly** выравнивает доли, не трогая закреплённые.

Включать и выключать офферы в обёртке нельзя: для этого есть удаление с архивом. Если оффер выключили
в самом Keitaro, обёртка покажет бейдж `disabled in KT` и сохранит его состояние при пуше.

**Изменения в Keitaro мимо обёртки.** При открытии кампании и по кнопке **Fetch streams from KT**
обёртка перечитывает потоки из Keitaro и сверяет их с черновиком:
* оффер, удалённый в Keitaro, всегда уходит в архив обёртки, даже если в черновике есть незапушенные правки;
* оффер, добавленный в Keitaro, появляется в черновике, поэтому следующий пуш его не затрёт;
* если в Keitaro поменяли долю, обновляется бейдж «что в Keitaro»; при чистом черновике доля
  просто берётся из Keitaro;
* найденные изменения перечислены над таблицей потока в блоке **Changes made in Keitaro**.

В списке кампаний жёлтая точка отмечает кампании с незапушенными правками.

## API обёртки

| Метод и путь | Что делает |
|---|---|
| `GET /api/meta` | Офферы, домены, группы, источники и значения по умолчанию для форм |
| `GET /api/campaigns` | Кампании из Keitaro: `created_here` — создана обёрткой, `has_draft` — есть незапушенные правки |
| `POST /api/campaigns` | Создать кампанию: `{"name", "geo", "offer_id", "domain_id?", "group_id?", "traffic_source_id?"}`; `geo` — строка `"MX, AU, RO"` или список кодов |
| `GET /api/campaigns/{id}` | Кампания и потоки из Keitaro со сверкой черновика; в `draft.kt_changes` — что поменяли в Keitaro. Этот же запрос делает кнопка Fetch streams from KT |
| `DELETE /api/campaigns/{id}` | Удалить кампанию вместе с потоками |
| `POST /api/streams/{id}/offers` | Добавить оффер `{"offer_id"}` в черновик |
| `DELETE /api/streams/{id}/offers/{offer_id}` | Пометить оффер на удаление |
| `POST /api/streams/{id}/offers/{offer_id}/restore` | Вернуть из архива или отменить удаление |
| `PATCH /api/streams/{id}/offers/{offer_id}` | Изменить `share` (остальные подстроятся) или `pinned` |
| `POST /api/streams/{id}/rebalance` | Распределить доли поровну с учётом закреплений |
| `POST /api/streams/{id}/discard` | Отменить незапушенные правки (черновик = Keitaro) |
| `POST /api/streams/{id}/push` | Отправить черновик в Keitaro |
| `GET /api/history?campaign_id=` | История изменений офферов |

Создание кампании атомарно с точки зрения пользователя: если какой-то поток не создался,
обёртка удаляет только что созданную кампанию, чтобы в Keitaro не оставалось полуфабрикатов.
Перед созданием проверяется, что оффер существует. Ошибки Keitaro возвращаются с понятным текстом.

## Тесты

```bash
pytest -q
```

Тесты не ходят в настоящий Keitaro: клиент подключается к in-memory эмулятору (`tests/fake_keitaro.py`)
через `httpx.MockTransport`, так что проверяется реальный HTTP-код клиента. Покрыты распределение долей,
создание кампании с проверкой тела каждого потока, откат при ошибке, черновик и пуш, архив и возврат,
закрепления со всеми пограничными случаями, ручной ввод долей, отмена правок и изменения в Keitaro
мимо обёртки (в том числе поверх незапушенного черновика).

## Структура

```
app/
  main.py              FastAPI, обработка ошибок Keitaro, раздача фронта
  api.py               эндпоинты /api/*
  keitaro.py           клиент Admin API
  config.py            настройки из .env
  db.py, models.py     SQLAlchemy
  schemas.py           Pydantic-схемы
  services/
    campaigns.py       создание и удаление кампаний
    editor.py          черновик офферов, пуш, архив, сверка с Keitaro
    shares.py          правила долей и закреплений
  static/              интерфейс (HTML + JS + CSS)
alembic/               миграции
tests/                 тесты и эмулятор Keitaro
```
